여기에 뭘 만들면 되냐면, "부끄판" 이라는 웹사이트를 만들면 돼. 배포는 셀프호스팅으로 할 거야.
배포 자동화는 일단 만들고 나서 신경쓸게 지금은 일단 구현에만 집중해.
PWA 로 쓸 수 있어야 하긴 하는데 그것도 좀 나중에 처리할게.
부끄판이 뭐냐면 부끄 커플(나와 내 여친임)이 쓰는 그림판이야.
부끄판은 붓이라든지 선택 툴이라든지 이동 툴 그런 게 하나도 없어.
단지 무조건 붓이야. 근데 그 붓으로 터치한 대로 자유롭게 그려지는데
핵심은 그게 시간이 지나면 자연스럽게 서서히 사라져야 해.
그래서 지우개 툴이 필요없어.
화려한 효과도 넣을 거긴 한데 일단은 PoC 로 배포와 인프라 구축까지 해볼 거야.
그게 다 되고 한 사이클 돌고 화려한 효과를 추가할게.
지금은 단순히 검은 화면에 터치하는 대로 흰 줄이 그려지는 공유 그림판까지만 구현하면 돼.
그래서 지금 해야 하는 건
순수 자바스크립트로 그걸 구현하는 거야. (라이브러리를 가져다 쓰지마)
아마도 HTML Canvas 를 쓰는 게 좋지 않을까 싶긴 한데 기술적인 선택은 모두 너에게 맡길게.
공유를 위한 통신은 Web Socket 을 쓰면 돼.
단일 서버로 통신할 거고 단 두 명의 클라이언트가 단일 세션 상태를 이용할 거야.
쓸데없이 멀티 세션을 고려할 필요 없어.
상태 공간은 단순히 서버의 메모리야. 영속성은 전혀 고려할 필요 없어.
인증 인가는 나중에 넣긴 할 건데 일단 지금은 인증 인가 건너뛰고 무조건 허용해.
지금은 PoC MVP 를 만든다고 생각하고 단순히 구현해.
flake.nix 로 패키징해.
nix build .#default 하면 서버가 빌드되고
nix build .#client 하면 클라이언트가 빌드되면 돼.
nix run .#default 하면 서버가 실행되면 돼.
nix run .#dev-server 하면 서버와 클라이언트가 모두 서빙되는 reverse proxy 서버가 실행되면 돼.
개발자는 nix run .#dev-server 를 하고 브라우저에서 localhost:3000 에 접속해서 확인할 수 있어야 해.
서버는 raspberry pi 가 될 거라서 적은 메모리를 잡아먹는 언어를 쓰면 좋아.
실제로 배포할 땐 caddy 를 써서 서버앱과 클라이언트 asset 을 서빙할 거야.
서버에는 이미 caddy 가 돌아가고 있어서 sub domain 기반으로 라우팅 할 거야. caddyfile 모듈 방식을 쓸 거야.
표준적으로 많이 쓰이는 경로에 이 부끄판 caddy 모듈을 넣으면 상위 caddy 모듈이 그걸 import 해서 함께 서빙하는 식이야.
그걸 위해서 nix run .#install -- /path/to/bukupan/Caddyfile --srv-path /path/to/bukupan/srv 이런 느낌의 사용도 지원해야 할 거야.
화면은 현재 뷰포트의 width, height 를 꽉 채워서 쓰면 돼. 모바일 브라우저는 주소창을 숨기기 위해서 실제 뷰포트보다 큰 값을 쓸지도 모르는데 그냥 무시하고 꽉 채우고 스크롤바도 그냥 숨겨버려 경계는 중요하지 않아. 그냥 화면 꽉 채우게 그림판이면 돼.
UI 버튼이나 브랜딩, 로고 이런 건 하나도 필요 없어. 나중에 PWA 를 위한 최소한의 asset 을 또 만들긴 할 건데 지금은 그냥 대충해
인증 인가 나중에 넣는다고 했지만 이걸 위한 로그인 버튼 같은 건 필요 없어. 특별한 숨겨진 커맨드 행동을 만들어서 그걸 하면 로그인 페이지로 보낼 거야. 아직은 이걸 고려하지 않아도 돼.
서버의 시스템은 aarch64-linux 가 될 건데 개발 환경은 x86_64-linux, aarch64-darwin 이니까 flake 도 딱 그 세 system 만 지원하면 돼.
이때 flake-utils, flake-parts 는 도입하지 말고 ~/ws/fall 에서와 비슷하게 forAllSys 같은 거 간단히 짜서 쓰는 식으로 해.
친절한 readme 는 필요없어. 나중에 내가 보고 설치할 수 있게 최소한의 instruction 만 있으면 돼.
유지보수에 필요한 내용이 있다면 contributing 문서를 만들어서 거기에 쓰면 돼.
라이선스는 mit 야.
github 공개 저장소로 공개할 거야. 저장소는 미리 파뒀어 github:hooreique/bukupan 이야.
flake 평가가 중간중간 필요할 텐데 그걸 위해서 git add 하면서 해. 안그러면 평가가 불편할 거야.
테스트는 별로 중요치 않아. 너무 무거운 테스트 환경을 도입하지마.
